# TypeScript + Go website

The frontend uses TypeScript and Vite, with Node.js running the development and build tools. Go provides the HTTP API using its standard library. Nginx serves the built frontend and forwards API requests in production.

## Prerequisites

- Node.js 22.12+ and npm: https://nodejs.org/en/download
- A currently supported Go release (module minimum: 1.22): https://go.dev/doc/install
- Nginx for production deployment only.

## Develop

From this folder:

```sh
npm install
npm run dev
```

Open http://localhost:5173 and click **Check API connection**. Vite forwards `/api` to Go on port 8080. Both servers bind to the local machine. Ctrl+C stops both processes.

Commit the package-lock.json generated by npm install.

## Check and build

```sh
npm run check
npm run build
```

The frontend build is in `frontend/dist`; the Go executable is `bin/server`.

## Deploy with Nginx

1. Build for your deployment operating system and architecture.
2. Copy frontend/dist to /var/www/website/frontend/dist, or adjust the Nginx root.
3. Run bin/server under a process manager such as systemd on the same host as Nginx.
4. Adapt deploy/nginx.conf with your domain and install it in your Nginx configuration.
5. Validate with `nginx -t` before reloading Nginx.
6. Configure a TLS certificate and HTTPS for your domain before public use; the supplied configuration is an HTTP starting point.

Nginx preserves the `/api/` prefix when forwarding requests. Node.js is needed for building the frontend; production runs Nginx and the Go executable.

## File uploads

Use the top menu to switch between Main and Uploads. Select files and click **Upload files**, or drag files onto the Uploads page to start uploading immediately into the current folder; each file is sent separately with no fixed application size limit. Uploads stream directly to disk without multipart temporary-file buffering; available server disk space still limits storage. Upload duration is controlled by `upload_timeout_seconds` (default 120 seconds), and interrupted transfers are removed (resumable uploads are not supported). The server saves files under their original filenames, outside the public frontend directory. Uploads persist across server restarts.

Set `UPLOAD_DIR` to an absolute directory for production storage (the default is `uploads` relative to the server working directory). The server process needs write access to this directory. Original filenames are retained on disk. Duplicate filenames are rejected without overwriting existing files. The Uploads screen lists files and folders inside this directory and allows permanent deletion after confirmation. Create folders, open them, and use Up one folder to navigate. Uploads go to the selected folder. Symbolic links and paths outside the configured root are excluded. Files and folders can be deleted in the selected folder. Folder deletion warns before permanently removing all nested contents; Cancel leaves the folder untouched. Older uploads retain their generated storage names because their original names were not saved. No download interface is provided. The upload endpoint currently has no authentication, so access should be restricted before hosting it publicly.

The Uploads page shows available space on the current folder’s filesystem (including nested mounts). It refreshes every 15 seconds while visible and when the file list refreshes after uploads or deletions. Less than 25% free shows an orange warning; less than 10% shows a red critical alert. Space excludes filesystem blocks reserved from normal users. Disk space reporting requires a Linux API host.

### Plex access to uploads

The uploader requests `0770` for upload directories and `0660` for files, allowing parent default ACLs to grant Plex read access. Without a default ACL, the process umask controls group permissions. These modes also allow the owning group to write when permitted by the umask or ACL; use a dedicated upload group. Other users receive no access through the creation modes. State and cache directories remain private.

After deploying the rebuilt API and restarting it, run this once on the server to grant Plex access to existing videos and set inheritance for future folders and files:

```sh
media_root='/mnt/24998300-2374-4a05-8e00-2450abc47fa0/uploads/videos'
sudo find "$media_root" -type d -exec setfacl -m u:plex:rx,d:u:plex:rx {} +
sudo find "$media_root" -type f -exec setfacl -m u:plex:r {} +
```

Default ACLs propagate into new subfolders. New files inherit read access without execute permission. The old uploader's `0700`/`0600` modes masked inherited Plex permissions, so both the code update and the default ACL setup are needed. This requires filesystem ACL support and the `setfacl` utility. Plex also needs traverse (`x`) access to every ancestor of this video directory; grant that on any restricted ancestor if needed. Verify access with `sudo -u plex test -r '/full/path/to/movie.mp4'` (exit status 0 means readable). These commands apply to the video tree; repeat for other media roots if needed.

### Troubleshooting remote uploads

Deploy both `frontend/dist` and the rebuilt `bin/server`, then restart the Go service. Updating frontend files alone leaves the old API running without the upload endpoint.

The upload screen reports HTTP errors. For 404 or 405, check that the updated Go server is running and `/api/` is proxied to it. For 500, inspect the Go service logs for the storage error and set `UPLOAD_DIR` to an absolute directory writable by the service user. For 502, check the Go service is listening on `127.0.0.1:8080`. For 413, apply `client_max_body_size 0;` in the active Nginx server block, validate with `nginx -t`, and reload Nginx. The supplied configuration also disables request buffering and uses 300-second inactivity timeouts so large uploads stream directly to Go.

To isolate the API from Nginx, run these on the server, using a small existing file:

```sh
curl -i -F 'file=@/path/to/small-file.txt' http://127.0.0.1:8080/api/uploads
curl -i -F 'file=@/path/to/small-file.txt' https://your-domain.example/api/uploads
```

Each successful diagnostic request saves a file. If the direct request succeeds and the public request fails, check the active Nginx configuration and logs.

## Video streaming

Open Videos in the top menu, navigate uploaded folders, and select videos using checkboxes. Play selected starts a playlist in the browser; selection spans folders and is saved automatically on the server across visits and restarts. Clear selection also clears the saved selection. The selection is shared across browsers and devices; open pages synchronize every three seconds and when focused. The last saved selection wins. Settings are stored in `UPLOAD_DIR.state/video-selection.json` (default `uploads.state/video-selection.json`), outside the browsable upload folder. Keep this directory writable by the server and include it in backups. Stream links can be opened or copied into other players. MP4/M4V, WebM, Ogg, MOV, and MKV files are listed; playback depends on browser codec support. No transcoding is performed.

`GET /api/videos/{filename}?path=folder/subfolder` streams a video from the upload root with HTTP byte ranges for seeking and HEAD support. It uses the same folder restrictions as file management. Stream links currently require no authentication, just network access to the server.

### Embedded audio and subtitle tracks

Install `ffmpeg` and `ffprobe` on the server PATH, then restart the API. The player offers embedded audio tracks and text subtitles. Selecting audio copies the video and converts that audio to stereo AAC in a cached MP4; first preparation can take minutes and requires space for another copy of the video. Subsequent playback supports seeking. Video codec compatibility still depends on the browser. Original files are unchanged.

Text subtitles (SRT, ASS/SSA, WebVTT, MOV text) are extracted as WebVTT; styling may be lost. Image subtitles are listed as unsupported. Cache files live in `UPLOAD_DIR.state/media-cache`; they may be removed while the server is stopped to reclaim disk space. If using Nginx, raise `proxy_read_timeout` for initial conversion of long videos.

## Server configuration

Edit `backend/config.json` to choose where uploads are saved:

```json
{
  "upload_dir": "/mnt/media/uploads",
  "upload_timeout_seconds": 120
}
```

The server checks the config file every second and automatically applies valid changes to new requests. Active requests keep their original settings. Invalid or missing files are logged and the last valid settings remain active until the file is fixed. Absolute paths can point to a different mount. Relative paths resolve from the configuration file's directory, so the default `uploads` remains `backend/uploads`. The server logs the resolved directory at startup. The server user needs write access to this folder and its sibling state directory (`/mnt/media/uploads.state`). Existing files and saved selections are not moved automatically.

`upload_timeout_seconds` sets the Go server request read and response write limits in seconds. Omit it to keep the 120-second default, use `600` for ten minutes, or `0` for no read/write duration limit. Negative, fractional, and excessively large values are rejected. These server-wide limits also affect downloads and video streams. Changes take effect automatically. Nginx has independent inactivity timeouts in `deploy/nginx.conf`; adjust those separately if necessary. The browser does not impose an application upload timeout.

`UPLOAD_DIR` still overrides the file setting when set. For a built server, specify the config path explicitly when running from the project root:

```sh
./bin/server -config backend/config.json
```

You can use a separate machine-specific config file with `-config /path/to/server.json`. Invalid or missing configuration at startup stops the server with an error. Once running, reload errors retain the last valid settings.

## File downloads

Use Download beside a file on Uploads for an individual download. Check files (or the header checkbox for all files in the current folder) and click Download selected as ZIP. Archives include up to 200 selected files from the current folder and stream directly to the browser download manager. Folder downloads are not included.
